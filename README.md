# astrbot_plugin_smart_reply ｜ 智能自动回复

![logo](logo.png)

在你指定的群里，监测到「内容」就自动回复「内容」，可附带一张图片，带冷却防刷屏。
不需要它开口的群、人、时段都可以挡在外面；规则没命中时还可以让模型判断一句
「这话该不该接」——先按频次粗筛，只有灰区才问一次模型，同一串消息判过就复用，
被无视就自动降频。

## 特性

- **只在特定群生效**：把 `group_target_mode` 设为 `whitelist` 并填上群号，没进白名单的群完全不参与
- **范围可控**：群与用户各自可选「不限制 / 仅白名单 / 仅黑名单」，黑名单优先级最高
- **规则级范围**：每条规则可再写「生效群号 / 生效QQ号」，只在指定群里冒头
- **语境判断**：规则没命中时先按消息频次粗筛，冷清与刷屏都不打扰，只有灰区才问一次模型
- **省着用模型**：同一串消息判过即复用（`ctx_cache_ttl` 内直接套用结论），同一群两次判断还有最小间隔
- **被无视就降频**：回复后没人接话算一次「被无视」，累计到阈值自动抬高门槛、拉长冷却；有人接话立刻复位
- **规则自定义**：想监测什么、回什么，全在配置里写，无需改代码
- **附带图片**：只写图名即可（自动在图片目录里找并补扩展名），也支持绝对路径和 http(s) 链接
- **防刷屏**：同一条规则在冷却时间内不重复发送，冷却范围可选按群 / 按人 / 全局
- **不重复回复**：同一条触发词刚刚在「上面」出现过就跳过，可在配置里用一个开关随时关掉
- **三种匹配**：`contains`（包含，默认）/ `exact`（完全相等）/ `regex`（正则）
- **开关齐全**：群聊、私聊分别开关；机器人自己发的消息默认不触发（防死循环）
- **改配置即生效**：在 WebUI 里改规则后不需要重载插件

## 只想在特定群触发

1. `group_target_mode` 选 `whitelist`，`group_whitelist` 填群号（逗号、分号、顿号都行）；
2. `enable_private` 关掉，私聊就彻底不参与；
3. 想让某个群完全安静，把它加进 `group_blacklist`（任何模式下都优先拦截）。

之后只有这些群里的消息会进入后续流程，语境判断也受同一道门槛约束。

## 规则写法

每条一行，逗号分隔：

```
触发词，回复内容，图片，冷却秒数，生效群号，生效QQ号
```

后五项都可以省略：

| 配置 | 含义 |
|---|---|
| `姆唔，姆唔，tu_1` | 监测到「姆唔」→ 回复「姆唔」+ 图片 `tu_1` |
| `早安，早安哦` | 只回复文字 |
| `晚安，，tu_2，120` | 只发图，冷却 120 秒 |
| `签到，签到成功，，0，123456` | 只在 `123456` 这个群里触发 |
| `摸头，好啦好啦，，0，123456+789，111` | 只在两个群里、且只对 `111` 触发 |
| `你是笨蛋，哼，别说了` | 回复「哼，别说了」（注意：回复里带逗号时请用 JSON 写法） |

群号 / QQ 号支持用 `+`、逗号、分号、顿号或空格分隔多个。

图片只写图名时，会在 `image_dir`（默认 `/root/AstrBot/data/workspaces/tu`）里查找，
`tu_1` 会自动匹配 `tu_1.png` / `tu_1.jpg` 等。

### 高级写法（JSON）

规则列表也支持 JSON 数组，字段更灵活，回复内容里可以带逗号：

```json
[
  {"keyword": "姆唔", "reply": "姆唔，姆唔", "image": "tu_1"},
  {"keyword": "早安", "reply": "早安哦", "cooldown": 60},
  {"keyword": "签到", "reply": "签到成功", "groups": ["123456"]},
  {"keyword": "摸头", "reply": "好啦好啦", "groups": ["123456", "789"], "users": ["111"]},
  {"keyword": "^好耶+$", "reply": "好耶！", "match_type": "regex", "image": "https://example.com/a.png"}
]
```

字段：`keyword`（必填）、`reply`、`image`、`match_type`、`cooldown`、`groups`、`users`。

## 触发范围（白名单 / 黑名单）

群与用户各有独立一套，模式先选，再填名单（逗号、分号、顿号、空格或换行分隔都行）：

| 模式 | 行为 |
|---|---|
| `off`（默认） | 不做白名单限制，但黑名单依然生效 |
| `whitelist` | 只有白名单里的群 / 人才触发；**白名单为空则一律不触发** |
| `blacklist` | 黑名单里的群 / 人不触发，其他都触发 |

- 黑名单优先级最高：同时出现在两份名单里，按不触发处理。
- `ignore_user_ids` / `ignore_group_ids` 视为黑名单的一部分，旧配置照旧生效。
- 群聊消息会同时过用户与群两道校验；私聊只过用户一道。
- 规则里写了生效群号时，**私聊永远不触发这条规则**（没有群号可比）。

### 两层范围怎么叠加

先过全局（上面那两张模式表），再过规则自己写的群号 / QQ 号，两层都放行才会回复：

```
消息 → 群聊/私聊开关 → 机器人自检 → 用户白黑名单 → 群白黑名单 → 规则级群号 | QQ号 → 去重 → 冷却 → 发送
```

## 语境判断回复（实验）

默认**关闭**，`context_judge_enabled` 打开后，规则全都没命中时才会走这条路：
不是每条消息都去问模型，而是先用**频次**粗筛，只有落在灰区的消息串才动用 LLM。

```
消息 → 规则命中？→ 命中就照旧回复
                ↘ 没命中 → 频次粗筛
                            冷清（消息太少 / 已经聊完了）→ 不回复，也不问 LLM
                            刷屏（短时间内条数超过阈值）→ 不回复
                            被点名（@ 机器人 / 叫了名字）→ 直接交给 LLM
                            灰区 → 查缓存 → 命中就复用上次结论
                                          ↘ 没命中才调一次 LLM，结论写回缓存
```

- **粗筛靠频次**：窗口 `ctx_window_seconds` 内条数少于 `ctx_min_msgs` 视为冷清；
  超过 `ctx_spam_msgs`（0 表示不看这条件）视为刷屏；两种都不打扰，也不花 token。
- **同一串消息只问一次**：缓存签名取最近 `ctx_cache_span` 条消息（去掉空白差异），
  同一个会话在 `ctx_cache_ttl` 秒内重复出现同样的串就直接复用结论。
- **判断结果**：模型只回单行 `YES` / `NO` / `YES|回复内容`；回不出来或者乱回一律当 `NO`，
  宁可不打扰。`ctx_reply_max_chars` 限制回复长度。
- **代价控制**：同一群两次判断至少间隔 `ctx_min_interval` 秒，另有 `ctx_cooldown_seconds` 语境回复冷却。
- **被无视就降频**：回复后 `ctx_ack_seconds` 秒内没人接话算一次「被无视」；
  累计 `ctx_ignore_limit` 次开始降档，每档把粗筛门槛抬高 `ctx_level_step` 条、
  冷却乘以 `ctx_backoff_base` 的幂（上限 `ctx_backoff_cap`），最高 `ctx_max_level` 档。
  有人接话立刻清零，回到正常。
- 语境回复同样要过群 / 私聊开关、白名单黑名单；私聊默认不参与，需另开 `ctx_private_enabled`。
- 模型只回 `YES` 时用 `ctx_fallback_reply` 顶上；它留空就直接不发送（宁可安静）。

## 配置项

| 配置 | 默认 | 说明 |
|---|---|---|
| `rules` | `[]` | 规则列表，见上 |
| `match_type` | `contains` | 默认匹配方式 |
| `cooldown_seconds` | `30` | 默认冷却秒数，0 为不限制 |
| `cooldown_scope` | `group` | 冷却范围：`group` / `user` / `global` |
| `cooldown_hint` | 空 | 冷却期间只提示一次的话术，留空则静默 |
| `image_dir` | `/root/AstrBot/data/workspaces/tu` | 图片名查找目录 |
| `enable_group` | `true` | 群里是否生效 |
| `enable_private` | `true` | 私聊是否生效 |
| `ignore_bot` | `true` | 忽略机器人自己的消息 |
| `ignore_user_ids` | `[]` | 不触发回复的 QQ 号（等效于用户黑名单） |
| `ignore_group_ids` | `[]` | 不触发回复的 QQ 群号（等效于群黑名单） |
| `group_target_mode` | `off` | 群聊触发范围：`off` / `whitelist` / `blacklist` |
| `group_whitelist` | `[]` | 群白名单，仅在 `group_target_mode=whitelist` 时生效 |
| `group_blacklist` | `[]` | 群黑名单，任何模式下都生效 |
| `user_target_mode` | `off` | 用户触发范围：`off` / `whitelist` / `blacklist` |
| `user_whitelist` | `[]` | 用户白名单，仅在 `user_target_mode=whitelist` 时生效 |
| `user_blacklist` | `[]` | 用户黑名单，任何模式下都生效 |
| `no_quote` | `true` | 回复时不引用原消息（直接发送，绕过框架的引用装饰） |
| `dedup_enabled` | `true` | 上面已有触发词就不再回复（去重总开关，配置界面里就是一个开关） |
| `dedup_window` | `1` | 往上检查几条消息，`1` 只看紧邻的上一条 |
| `dedup_seconds` | `0` | 只统计这么多秒以内的上面消息，`0` 表示不限时间 |
| `dedup_same_user_only` | `false` | 只算同一个人说的；默认关闭，即上面谁说过都算 |

## 行为说明

- 一条消息只触发**第一条**命中的规则，按配置顺序优先。
- 命中后会先看去重：**上面已经出现过这条触发词就不再回复**（`dedup_enabled` 关闭则跳过这一步）。
- 去重只看「上面」的消息，不看本条自己；记录按会话（群 / 私聊）隔离，只存内存，重启即清空。
- 命中后先判断冷却，冷却中不发送（配置了 `cooldown_hint` 则最多提示一次）。
- 规则只有图片但图片找不到时，不会发送空消息，会在日志里给出警告。
- 冷却记录保存在内存里，插件重载或 AstrBot 重启后清空。

